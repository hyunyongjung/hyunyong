## 1. 계정과 팀

부원 2명이 한 팀으로 진행합니다. 담당 임원진 1명도 원하면 같은 팀에 합류할 수 있습니다(팀당 최대 3명). 프로젝트명 아래에는 합류한 사람의 본명이 표시됩니다. 다른 팀에 남기는 피드백에는 자동으로 배정된 닉네임이 표시되며, 임원진은 감독 모드에서 작성자의 본명을 확인할 수 있습니다.

## 2. 웹앱 제작

지난주 아이디어에서 사용자가 직접 해볼 행동 하나를 골라 웹앱으로 구현하세요. 처음 시작하는 팀은 누구의 어떤 불편을 해결할지 먼저 정하세요. 두 사람 모두 핵심 기능을 직접 써보세요.

## 3. GitHub README

팀 GitHub 저장소의 README.md에 아래 일곱 항목을 작성하세요. 이미 쓴 팀은 빠진 항목만 채우세요. README를 볼 수 있는 주소를 복사하세요.

## 4. 프로젝트 등록

팀 카드의 ‘프로젝트 수정’에서 프로젝트명, 한 줄 소개, GitHub README를 저장하세요. 다른 사람이 웹앱을 열어볼 수 있다면 실행 링크도 넣으세요. 내 기기에서만 실행되는 경우 발표 때 직접 시연하세요.

## 5. 발표자료와 확인

같은 팀 카드에 PDF(15 MB 이하)를 올리거나 Canva·Google Slides 등의 보기 링크를 등록하세요. 발표자료를 GitHub에 따로 올릴 필요는 없습니다. 다른 팀원이 자기 기기에서 README, 웹앱 링크(있는 경우), 발표자료를 하나씩 열어보세요.

## 6. 데모데이 · 12월 1일

팀 카드에서 발표자료를 열고 핵심 기능을 시연하세요. 다른 팀의 프로젝트에 닉네임으로 피드백을 남길 수 있습니다. 투표는 자기 팀을 제외하고 최대 두 팀까지 가능하며, 운영진이 결과를 공개하기 전까지 선택을 바꿀 수 있습니다.

## 팀 프로젝트 README 틀

아래를 복사해 각 팀의 README.md에 붙여 넣고 질문을 팀의 답으로 바꾸세요.

```md
# Project Name

## Target User
누가 어떤 상황에서 이 웹앱을 쓰는가?

## Problem
그 상황에서 사용자가 겪는 구체적인 불편은 무엇인가?

## Prototype
이번 버전에서 직접 써볼 수 있는 핵심 기능 하나는 무엇인가?

## Core Interaction
사용자가 무엇을 하면 화면에서 무엇이 달라지는가?
‘사용자 행동 → 화면 변화’ 한 줄로 적기.
예) 원하는 구도를 선택한다 → 사진 위에 구도 가이드가 나타난다.

## Trade-off
이번 버전에서 미룬 기능은 무엇이고, 왜 미뤘는가?

## Next Steps
실제 서비스로 발전시킨다면 무엇부터 고려해야 하는가?
아래 예시 중 팀에 가장 중요한 것 하나를 골라 적기.
- 비용: 운영비는 어디에서 발생하는가? (예: API, 서버, 데이터 수집)
- 수익화: 누가 어떤 가치에 돈을 낼 만한가?
- 확장: 다음 버전에서 어떤 기능을 먼저 추가하고 싶은가?

## Reflection
직접 써보니 예상과 달랐던 점은 무엇인가?
예) 다른 팀원이 어느 화면에서 멈췄고, 그걸 보고 무엇을 바꿨는가?
```
